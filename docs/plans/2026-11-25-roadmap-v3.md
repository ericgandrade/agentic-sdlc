### v3.1 design notes: the unattended driver

These patterns specify the `run-driver.mjs` and authority-guard rows above. Each one has a working precedent elsewhere. Build on `preflight.mjs` and `run-ledger.mjs`; do not start a second state store.

**Control loop**

| # | Pattern | Rule | Criterion |
|---|---|---|---|
| D1 | Deterministic controller, ephemeral agent | The driver contains no model calls. It launches one fresh non-interactive agent session per task and judges the outcome only from files on disk and git state, never from the agent's claim | C4, C8 |
| D2 | Ordered outcome contract | A task is done only if, in order: terminal status in the task file, a fresh final review recorded, clean tree, non-empty diff, base commit is an ancestor, no protected path touched. The first failing rule decides the verdict and is written to the ledger | C4 |
| D3 | Environment fault is not task failure | Classify exits: command not found, not executable, setup failure, or a configurable exit code → `env_fault`. It pauses the run as resumable and does not consume an attempt | C6, C8 |
| D4 | Per-task state machine | Phases `pending → running → verifying → reviewing → done / deferred / blocked`, with an attempt counter, a defer-or-block policy per group, and "skip the rest of the group" after a blocking failure | C6 |
| D5 | Write intent before acting | Append the attempt record (task, phase, base commit) before launching the session; `resume` re-enters by the recorded phase and is idempotent | C8 |
| D6 | Crash-safe persistence | State snapshot written via temp file + fsync + rename. The ledger is append-only JSON Lines with fsync; on read, ignore only a torn last line, fail on any other invalid line | C8 |
| D7 | Idempotent integration | Each integration commit carries a marker with the task ID. On resume, search from the recorded tip; if a squash was interrupted, undo and repeat it | C8 |
| D8 | One worktree and branch per task | Created from the target tip. On failure keep it and save a patch for analysis; clean up only on success. The worktree must sit **outside** the directory that holds driver state (see [Patterns to avoid](#patterns-to-avoid), P1) | C8 |
| D9 | Stall detection apart from the total timeout | Activity signature = hash of recent agent output + workspace mtimes (excluding dependency and build folders) + HEAD. A separate stall timeout and a separate overall cap | C6 |
| D10 | Turn end by machine signal | Pin the main session ID at launch. Count only stop events with that ID (subagent stops are ignored). If the agent stops before the outcome contract holds, inject a bounded number of "continue" nudges, then halt | C6 |
| D11 | Passive hook relay | `agentStop` / `subagentStop` hooks only copy allowlisted fields into an events folder, are a no-op outside a driver run and always exit 0. The driver reads the folder; the agent process is never coupled to the driver | C8 |
| D12 | Single exit protocol | Every halt writes status and blocking condition to the ledger, then runs a configurable termination hook. Distinct exit codes for done, paused-resumable, blocked and failed. Never reuse one code for two states (P10) | C8 |

**Authority guard** (the C8 4 → 5 row)

| # | Pattern | Rule |
|---|---|---|
| G1 | Environment built from an allowlist | Start from an empty environment, pass through declared variables only, then apply a final hardening dictionary last. Forge tokens (`GH_TOKEN`, `GITHUB_TOKEN` and provider equivalents) are removed from the agent session **and** from verify and setup commands |
| G2 | Push blocked at the VCS level | Rewrite every push URL prefix to a non-existent scheme via environment git config, empty `credential.helper`, set `GIT_SSH_COMMAND=false`, and do not pass `HOME`'s SSH keys. An explicit `pushurl` in repo config **fails** preflight; it does not just warn. Document it as protection against accidents, not against a hostile agent |
| G3 | Hardened git wrapper for the driver and every observer | Hooks path pointed at a verified empty folder, fsmonitor off, redirect variables removed, argv without a shell. Monitors and status views use the same wrapper |
| G4 | Control-plane snapshot | Hash `.git/config`, hooks, instruction files and method config before and after each phase (type, exec bit, content). Any change pauses the run with the reason; continue only after a human re-baseline |
| G5 | Protected paths | A diff that touches the driver, the method's instructions, the policy or CI files is rejected as `blocked`, compared case-insensitively |
| G6 | Fail-closed provider adapters | Each supported CLI has an adapter that builds the real argv, including its sandbox and deny flags. Managed flags are refused in user-supplied extra arguments. A rule that cannot be applied on a provider is an error, not a silent skip. Network off where the provider supports it |
| G7 | Preflight with remediation | Ordered read-only checks with `ok`, `warn` and `fail`; only `fail` blocks; each item prints the command that fixes it. Includes "guard active", "verify commands configured" and "no explicit pushurl" |
| G8 | Layered, frozen policy | Defaults → team (versioned) → personal (ignored by git). Scalars override, tables deep-merge, safety arrays only grow. Strict schema per layer; unknown keys refuse the run. The resolved policy is frozen with a hash per layer at `run`; `resume` compares the hashes and asks for explicit acceptance if any changed |

**Tests that ship with the driver:** a refused push; a resumed run after a kill between "intent written" and "session launched"; a torn last ledger line; a stalled session; a changed policy layer on resume; a diff touching a protected path.

### v3.2 additions: method layer

No score projection is attached to these rows. They count only after an independent re-score of the built method.

| Item | Rule | Criterion | Effort |
|---|---|---|---|
| Frozen intent block in `spec.md` | A read-only block holds the approved intent; amendments go outside it with a change log. A check fails Build if the block changed after approval | C2, C10 | S |
| Review triage with root-cause classes | Two context-free reviewers see the diff **and** the spec. The context-holding agent re-assigns severity and classifies each finding: `intent_gap` (halt, back to the PO), `bad_spec` (amend spec outside the frozen block, re-derive), `patch` (fix code), `defer`, `reject` (reason recorded). Bounded rounds. The driver reads and validates the triage log; a log that skips a finding fails the outcome contract | C5, C6 | M |
| Evidence tiers for findings | Confirmed / probable (with a verifiable condition) / open question (kept out of the report). Zero findings is an accepted outcome; never require a minimum count (P18) | C5 | S |
| Review ordered by blast radius | Human walkthrough orders files: public API > core > error paths > infrastructure > tests | C5 | S |
| Next-step graph as data | One data file maps each skill to up to three recommendations (primary / secondary, condition, reason). The router reads it; CI validates that every referenced skill exists | C1 | S |
| Progressive help with confidence bands | Categories → items → detail; act / confirm / list / route by match confidence; never a dead end | C1 | S |
| Prerequisite check on activation | Declarative per-skill check of required artifacts (glob + severity), shown before the skill starts, with "create / proceed / abort". Advisory only: sign-offs stay the hard gate | C10, C1 | S |
| Persona as data | Role identity fixed; style, principles and menu configurable; before/after activation hooks; persistent facts loaded by file or glob. Resolved by the same layered resolver as the policy (G8) | C15 | S |
| Canonical source with generated discovery shims | One canonical skill tree; per-host shims ("read the canonical file") are generated, marked as generated, drift-checked in CI and orphans deleted | C15 | S |
| Catalog validator with rules as data **and** an engine | Declarative rules (required sections, patterns, cross-references, severity) executed by a script in CI that fails on error. A rules file without an engine is not shipped (P14) | C15 | M |
| Project context that holds only the non-obvious | Fixed sections: mandatory rules, project patterns, typical LLM pitfalls for this codebase, references. Exclude what is standard for the language. Human review before and after generation | C13, C14 | S |
| Typed append-only work log | One line per event (decision, assumption, crack, discard, lock), status as an event, final artifact distilled from the log, resume by status. Adapt from BMad's MIT `memlog` and credit it in `THIRD_PARTY_NOTICES.md` | C13, C8 | S |
| Memory rubric with mandatory dry-run | One rubric file lists what qualifies and what is noise, with edge cases. Saving always previews (accept / edit / cancel). Name, index and dedupe done by a script, not by the model (P20) | C16 | S |
| Lessons as reusable knowledge entries | Retro output becomes entries with `applies_when`, `avoid_when`, `severity`, `stack`, abstract `sources`, `generated` and human `verified`; deprecated, never deleted; schema-checked in CI | C16 | M |
| Lossless distillation with round-trip check | Compress long inputs for a downstream consumer, split above a budget, reconstruct and compare against the source; a deterministic check on numbers and entities | C13 | M |
| Idea interrogation with switchable roles | One question at a time in dependency order; attack / defend / switch commands; three valid exits, including "drop the idea". Feeds `brainstorming` before `spec-driven-development` | C2 | M |

## v3.3.0: runtime hardening and measured economy

| Item | Rule | Criterion | Effort |
|---|---|---|---|
| Token accounting where absence is not zero | Sum preserves nulls; dedupe by usage identity; reconcile with the session total; label coverage complete / partial / unavailable; only complete runs enter aggregates | C13, C16 | M |
| Cost computed at read time | Raw token counts are immutable; one formula applies a layered, dated price table (input, cache read, cache write, output, reasoning, long-context tier); unknown models show "no price", never 0; the table digest is recorded with each report | C16 | M |
| Cost attributed to tasks only by evidence | A receipt emitted by the task matched to call → run → success; explicit beats inferred; unattributed remainder shown explicitly; duration as a union of intervals | C16 | L |
| Telemetry privacy enforced by schema | Recursive validation rejects content keys (prompt, code, command text); commands reduced to signatures with a token allowlist; identities pseudonymized with a salted HMAC; minimal level by default; **no per-person metrics** | C11, C16 | S |
| Idempotent trace export | Trace and span IDs derived from a hash of the run and the logical path, so a resumed run never duplicates traces | C16 | S |
| One read-only projection for every view | A single observation module (bounded, last good value, freshness warning) feeds CLI and any UI; only the CLI can change state | C8 | M |
| Hardened local dashboard server | Exact Host and Origin allowlist, restrictive CSP, shutdown by a random token compared in constant time | C11 | S |
| Skill evals against the bare model | Same input, clean directory, with and without the skill; section ablation; a skill that does not beat the bare model is retired, not patched | C3, C13 | M |
| Grader with the burden of proof on "pass" | Binary per expectation with quoted evidence; uncertainty counts as fail; grader error is its own state; the grader reports weak or uncovered rubric items | C3 | S |
| Trigger detection by tool event | Measure whether a description activates a skill by counting only tool-call events that load a uniquely named synthetic copy; failures and timeouts are errors, not "did not trigger"; non-zero exit on any failure (P26) | C15 | M |
| State-prefix tests for multi-turn skills | A preamble declares where in the flow the test starts and what was already answered, so a mid-flow step is tested in one shot | C3 | S |
| Install with conflict-before-copy and three-way update | Dry-run at every layer; structural JSON merge with explicit conflicts; compare installed, current and new hashes before overwriting a user-edited file; transactional write with rollback (P21) | C1, C15 | M |
| Retired-files list | A fixed list of paths and keys removed on every update, without relying on the install record | C15 | S |
| Isolated, idempotent helper runtime | Own virtual environment per OS for helper scripts; exclusive lock with stale-lock detection; "not ready" sentinel; reinstall by requirements hash; never elevate privileges | C1 | M |

## Patterns to avoid

Observed in the reviewed implementation. Each one is a test case for the v3.1 driver and the v3.2 skills.

| # | Anti-pattern | Guard in this roadmap |
|---|---|---|
| P1 | The agent can write the driver's own state (worktrees inside the run directory, all-paths flag) | D8: worktrees outside the state directory; state path in G5 protected paths |
| P2 | Network left open on providers that support turning it off | G6 |
| P3 | Push block bypassable (`unset` of the env config, `HOME` SSH keys, explicit `pushurl` only warns) | G2 |
| P4 | Forge token still present in verify and setup commands, and visible in the process list through the terminal multiplexer argv | G1: pass the environment through a file or the process API, never argv |
| P5 | Observers running git in the agent's worktree without the hardened wrapper | G3 |
| P6 | Review triage, round cap and frozen-intent rule with no machine check | v3.2 review triage: the driver validates the log |
| P7 | Verify gate empty by default, so the contract alone decides | G7: preflight fails when no verify command is configured |
| P8 | Safety features (hooks, nudges, token scrubbing) on one provider only | G6: an unsupported rule is an error |
| P9 | Stall signal that walks dependency folders every few seconds and is reset by an animated spinner | D9 exclusions; strip animated regions from the output hash |
| P10 | One exit code for both "paused, resumable" and "failed" | D12 |
| P11 | Large modules with circular imports; three atomic-write implementations, one without fsync | One `lib/atomic.mjs` used by every script; module size budget in `budget-check` |
| P12 | YAML and frontmatter parsed by regex; blocking condition extracted from model prose | Real parsers; blocking condition as a structured ledger field |
| P13 | The same data hand-maintained in two formats that drift | One source format; others generated |
| P14 | A validator rules file that no code executes | v3.2 catalog validator ships with its engine |
| P15 | Scaffolders that emit invalid files and "continue if any manifest update fails" | Scaffolders validate output and stop on failure |
| P16 | References to skills that do not exist; orphan files nobody reads | Catalog validator cross-references |
| P17 | A skill description that advertises a mechanism the workflow does not implement | Catalog validator: advertised mechanisms must map to a step; same rule as the open `SKILL.md:146` CI claim |
| P18 | Coupled instructions that contradict each other ("find at least ten issues" vs "accept zero findings") | Evidence tiers; no minimum finding count |
| P19 | Hostile persona instead of method; arbitrary universal thresholds | Lenses defined by method and project DoD, not attitude |
| P20 | Critical logic left to model prose (fuzzy match scores, config writes, memory dedupe) | Scripts for anything that must be deterministic |
| P21 | Update that overwrites user-edited files without backup, file by file without rollback | v3.3 three-way update |
| P22 | A generic ~600-line `.gitignore` merged line by line into the user's project | Ship only the method's own ignore entries in a marked block |
| P23 | Identity sent in telemetry by default; per-person success rate suggested | v3.3 telemetry privacy |
| P24 | Telemetry that depends on markers the model must print | Measure from tool events and transcripts |
| P25 | Coverage pinned to a single CLI version | Version range with a compatibility test |
| P26 | Eval runners that count failures as success and always exit 0 | v3.3 trigger detection rules |
| P27 | Fork leftovers and inconsistent version strings across manifests | Extend `verify-version-sync.sh` to every manifest |
| P28 | Unpinned dependency (`@main`) and a publisher pulled from a mutable ref with cloud permissions | Pin by commit or version; no mutable refs in CI with write permissions |
