## Default path trace (scenario R)
Entry: README Quick Start: install CLI (curl script, npm or brew), `openspec init` in the existing repo; default 'core' profile installs skills explore, propose, apply, update, sync, archive (docs/getting-started.md). No size or risk routing: one default path; the expanded profile (new/continue/ff/verify/bulk-archive/onboard) is opt-in.
Brownfield (docs/existing-projects.md): optionally /openspec-explore to map the area to be touched; no need to spec the whole system (delta-first).
1. /openspec-propose <name>: clarify material ambiguity before creating; `openspec new change`; generate proposal.md (Why, What Changes, Capabilities, Impact), delta specs (### Requirement with SHALL/MUST, #### Scenario WHEN/THEN), design.md (conditional: Goals/Non-Goals, Decisions, Risks, Migration Plan with rollback), tasks.md (numbered checkboxes, each with its verification, tests landed per group). Stops at the planning boundary.
2. Human reviews the plan (docs/reviewing-changes.md two-minute checklist), then asks for /openspec-apply-change: tasks implemented in order, checkbox marked, pause on blockers or added scope.
3. 'Review the completed work' (verify is opt-in), then /openspec-archive-change: warns on incomplete tasks, syncs deltas into openspec/specs/, moves the change to changes/archive/YYYY-MM-DD-name/. Commits and PRs are the team's own (team-workflow.md 'OpenSpec doesn't touch git').
