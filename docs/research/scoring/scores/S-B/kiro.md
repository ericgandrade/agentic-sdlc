## Default path trace (scenario R)
Entry: install the IDE (download, run installer, sign in), open the existing repository (getting-started_installation.md, getting-started_first-project.md); optionally 'Generate Steering Docs', which analyzes the repository into product/tech/structure steering files.
Route for R: standard Feature Spec, not Quick Spec (best-practices: Quick Spec for well-understood features/prototyping; standard spec when 'your team benefits from explicit approval checkpoints') and not a vibe chat. Requirements-First is the default variant; Design-First is offered when an existing architecture constrains the work (both produce the same three files and gates).
1. Spec pane '+': Kiro asks Feature or Bug; requirements.md with user stories and EARS acceptance criteria (WHEN ... THE SYSTEM SHALL), edge cases; user reviews (Markdown Review) and confirms; Analyze Requirements is optional.
2. design.md: architecture, sequence diagrams, data models and interfaces, error handling, testing strategy; correctness properties extracted from EARS requirements; user confirms.
3. tasks.md: discrete tasks with dependencies, optional vs required tasks (property tests optional by default).
4. 'Run all Tasks': dependency graph, waves of concurrent tasks; default permission mode is Autopilot/'Accept file changes' (privacy-and-security.md). Web delivery ends with a pull request. Review, release and operations beyond that are the team's own.
