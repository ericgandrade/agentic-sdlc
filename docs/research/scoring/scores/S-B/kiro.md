Partial-access trace (closed product; documentation could not be opened): open the project in the Kiro IDE (or CLI) and start a Feature Spec from one prompt (P; README 'Use Specs to structure requirements, design decisions, and implementation tasks').
Route for R: Feature Spec, Requirements-First (the default variant per search snippet and P), not Quick Spec (which explicitly skips approval gates) and not vibe/chat mode.
1. requirements.md: user stories with numbered EARS acceptance criteria (WHEN ... THE <component> SHALL ...), glossary (official sample spec).
2. Pause for review, then design.md: architecture, components and interfaces, data models, 'Correctness Properties' each validating requirement numbers (sample; search snippet says standard specs pause between phases).
3. Pause for review, then tasks.md: two-level checkbox tasks citing '_Requirements: x.y_', optional ('*') unit and property-test tasks, 'Checkpoint - ensure all tests pass, ask the user' tasks (sample).
4. Task execution by the agent; optional Requirements Analysis and property-based correctness checks (README). Review, merge, deployment: not evidenced in accessible sources.
