## Default path trace (scenario R)

1. Install core-tools and method with two `npx skills add` commands, then ask the `bmad` skill for `bmad setup` (requires uv); `bmad` inspects project state and recommends the next skill. In an existing codebase, `bmad-project-context` writes a verified AGENTS.md block (recommended, skippable).
2. R is epic-sized (several Build sessions, one outcome; docs/plan/choose-a-planning-path.md): Sofia (`bmad-agent-po`) writes the epic's Requirements (stable `R<n>`), Constraints, `Done when`, Boundaries, Open questions, from any input; self-validates; slices into stories in `tickets.toml` with `after` edges; fresh-context subagents run the Set and Dependencies checks; `tickets.py status` checks cycles and order; the user approves the breakdown.
3. `bmad-build` per story (picked from `tickets.py next`): VCS and scope gates; investigation into a Code Map; risk scored; plan with frozen intent, I/O & edge-case matrix, Given/When/Then ACs, Verification commands; Open Questions halt; Checkpoint 1 approval (status `ready-for-dev`, frozen block locked).
4. Route auto: >100 LOC → full (fresh implementation subagent working only from the plan); verification commands and matrix test audit; review `quick` by default (one context-free reviewer), triage every finding into a logged verdict, loopback to plan or human (≤5 iterations), patches re-verified; local commit, never push; offer PR or `bmad-walkthrough`.
5. After the last story: `bmad-retrospective` (git evidence, review lenses over the epic diff, acceptance verdict, owned action items, follow-through on the previous retro). Method ends at commit/PR plus epic acceptance.
