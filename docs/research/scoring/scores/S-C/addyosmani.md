## Default path trace (scenario R)

1. Install as a Claude Code plugin (`/plugin marketplace add …`, `/plugin install agent-skills@addy-agent-skills`) or `npx skills add addyosmani/agent-skills`; the `using-agent-skills` meta-skill (session-start hook) routes tasks to skills. Brownfield teams follow docs/adoption-guide.md Path B (rules file of real conventions, characterization tests before change; new features run the full lifecycle).
2. `/spec` → spec-driven-development: clarifying questions, assumptions surfaced, SPEC.md (or a delta SPEC-<change>.md for an existing spec) with objective, commands, structure, style, testing, boundaries, testable success criteria, Out of Scope (Deferred), Open Questions; the agent stops its turn until the human approves.
3. `/plan` → planning-and-task-breakdown: dependency graph, vertical slices, tasks with acceptance criteria, verification, dependencies, files, size; checkpoints every 2–3 tasks; tasks/plan.md + tasks/todo.md for human review.
4. `/build` (one task at a time; or `/build auto` after one plan approval): RED test → GREEN minimum → full suite → build → commit → mark done; stop-the-line on failures; high-risk tasks go through doubt-driven-development with explicit sign-off.
5. `/review` (five-axis, Critical/Required/Optional/Nit) in the session, then `/ship` for a production-bound change: parallel code-reviewer, security-auditor and test-engineer subagents → merged GO/NO-GO with mandatory rollback plan; Critical → NO-GO by default. Skip of the fan-out allowed only for ≤2 files, <50 lines, no auth/payments/data/config.
6. shipping-and-launch: feature flags, staged rollout with thresholds, monitoring, error-budget gate, rollback plan.
