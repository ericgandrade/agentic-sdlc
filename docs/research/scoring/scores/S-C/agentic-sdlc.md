## Default path trace (scenario R)

Designed default path for R (D10 §1.1–1.6; R = feature with moderate risk → **Standard path**, §1.4: "Story, feature · one iteration, moderate risk, reversible with a plan"; risk signals such as personal data, money, public API or schema would escalate to Full):
1. **Plan** (Planner): intake, duplicate/prior-rejection check, classify, choose path by risk signals, set goal and indicator.
2. **Specify** (Planner + Security Auditor): `specs/<NNN-feature>/spec.md` with stories, AC-n in Given/When/Then, non-goals, constraints, security notes, rollback, indicator → **Spec approval** (Product Owner) recorded in `spec.md ## Approvals`; the agent ends its turn.
3. **Design** (Planner + Architect): ADRs for real decisions, `plan.md` with tasks inside (Standard) → **Plan approval** (Tech Lead), possibly combined with Spec approval on Standard.
4. **Build** (Implementer): task by task, test-first, small commits `[Tn, AC-n]`, PR; Build ⇄ Test fix loop capped at 5 rounds then escalation with a ruling on every open finding.
5. **Test** (Reviewer, read-only, fresh context; Test Engineer designs tests from the spec; Security Auditor): acceptance tests, independent code review, security review, PR Verification table AC-n → test → evidence → **PR approval** (branch protection / required checks "where possible").
6. **Release** (Release Engineer): feature flags, staged rollout, rehearsed rollback, release notes, runbook → **Release approval**. **Operate** (SRE): monitor the change and its indicator, incidents, postmortems; retrospective is a required artifact only on the Full path.
Most stage behaviour beyond §1 is listed in Phases B–D as "minimum additions (refine from the matrix)", i.e. mechanism names without behaviour; the existing skills (agentic-sdlc router, spec-driven-development, writing-plans, project-context …) give concrete text for some mechanisms but use the superseded 8-stage/CP vocabulary.
