## Default path trace (scenario R)

1. Install: one `curl … install.sh | sh`, then `aidlc config --harness claude` and `aidlc doctor` in the repo; open the harness and type `/aidlc <description>`.
2. Route: the conductor proposes a workflow profile from the description and the human confirms. For R ("production feature") docs/guide/workflow-profiles.md names **Feature** ("Choose Feature when: you are building a production feature"): all 30 stages at Standard depth, sensors/learnings/summary confirmation/plan approval on, skeleton on, Guard Policy `off`. Note: the engine's implicit default when nothing is named is Classic (harness/claude/settings.json `AWS_AIDLC_DEFAULT_SCOPE=classic`: advisory reviews, no Operation). Scored on Feature; cells where Classic would differ are flagged.
3. Initialization (state, scaffold, workspace detection) → Ideation (intent capture … approval handoff) → Inception: Reverse Engineering (brownfield codekb), Practices Discovery, Requirements Analysis (FR/NFR IDs, out-of-scope, ambiguity follow-ups), User Stories (AC IDs), Domain/Contract design, Units Generation (Unit DAG), Delivery Planning — each stage ends at a human approval gate.
4. Construction per Unit: functional/NFR/infra design (adversarial architecture reviewer), Code Generation with Plan Approval (testing contract: TDD/BDD/ATDD ordering, recorded Red output), reviewer refute-and-repair (≤2 passes), Unit checkpoint using a human-authorized verification command; optional swarm in worktrees for eligible batches.
5. Build and Test runs all commands, writes test-results.md with a Target Verification Matrix (Met/Not Met/Unverified), failure ladder (2 in-stage fixes → ≤3 loop-backs to Code Generation → halt-and-ask), cross-unit traceability gate via a deterministic sensor.
6. CI Pipeline, then Operation (conditional): deployment pipeline (rollback runbook, strategy), environment, deployment execution (pre-deploy checks, smoke/health), observability (alarms, SLOs), incident response (runbooks), performance validation, feedback & optimization (feedback document into next ideation). Learnings step before each gate when the human corrected the agent.
