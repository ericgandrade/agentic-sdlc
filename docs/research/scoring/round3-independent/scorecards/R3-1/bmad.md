## Default path trace (scenario R)
1. Install: `npx skills add .../skills/core-tools --skill '*'` and `.../skills/method --skill '*'`, then ask the `bmad` skill for `bmad setup` (README.md "V7 Preview Alpha"; docs/start/install-bmad.md). `uv` is required.
2. Entry point for a feature: `bmad-build` with the change (README.md "Start Building"). Route rule: `skills/method/bmod-method/help/help.md` "Routing" asks first "One session can understand, build, review and finish it?" → yes → `bmad-build`; `help/implementation-skills.md` sizes one session as "one goal, roughly 500 changed lines, not counting tests, in a handful of files"; `help/existing-codebase.md` "What pushes a change up a tier": "Size alone does not" — only an uncovered decision (new boundary, schema migration strategy, new authorization rules) does. A 3–10 task, single-goal feature that follows existing patterns therefore stays on `bmad-build` (free text, no ticket tree). Contestable: help.md also says "several people push work up from one session", and 20 files is more than "a handful"; on that reading the route is Sofia's ticket tree (initiative → epic → stories, each still built with `bmad-build`). Criteria whose score depends on this choice (C7, C9, C10, C16) carry Low confidence and name what the ticket-tree route would add.
3. Step 1 (`bmad-build/step-01-clarify-and-route.md`): load planning docs, VCS gate (dirty tree or branch mismatch → HALT), multi-goal check (split → `deferred-work.md`).
4. Step 2 (`step-02-plan.md`): investigation (subagents) → `route_selection` in `customize.toml` (≤100 LOC oneshot, else `full`; R is >100 LOC → `full`); writes `plan-<slug>.md` from `plan-template.md` (frozen Intent, Boundaries Always/Never, I/O & Edge-Case Matrix, Code Map, Tasks, Given/When/Then ACs, Verification), risk score, self-review vs READY FOR DEVELOPMENT, token gate (>1600), Open Questions HALT, CHECKPOINT 1 (human approves; status `ready-for-dev`; frozen block locked).
5. Step 3 (`step-03-implement.md`): baseline_revision, fresh implementation subagent with the plan as sole source of truth, diff staged and read by the orchestrator, `## Verification` commands run, Matrix Test Audit.
6. Step 4 (`step-04-review.md`): default `review = "quick"` (customize.toml) → one context-free Quick lens subagent; triage every finding (high/medium/low/false/maybe-false) into Review Triage Log; route intent_gap / bad_plan (loopback, cap 5 → HALT) / patch (re-engage implementer, re-run verification) / defer.
7. Step 5 (`step-05-present.md`): status `built`, local conventional commit, never push; offers PR, `bmad-walkthrough`. The user marks done.
